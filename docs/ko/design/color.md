# 색

<p class="plass-lede">여섯 개의 의미론적 계열, 계열마다 손으로 고른 값 둘, 그리고 나머지는 전부 계산됩니다. 이 페이지는 토큰이 무엇이고 어떻게 바꾸는지에 대한 것이고, 왜 이런 모양인지는 디자인 언어에 있습니다.</p>

## 여섯 계열

`color`는 값이 아니라 **역할**입니다. `color="#3558ef"`도 `color="blue"`도 없습니다. 컴포넌트는 여섯 이름 중 하나를 받고, 그 이름이 어떤 값이 되는지는 테마가 가진 결정입니다.

| 계열        | 라이트    | 어디에 쓰는지                          |
| ----------- | --------- | -------------------------------------- |
| `primary`   | `#3558ef` | 그 화면이 하려는 액션                  |
| `secondary` | `#4f5a70` | 그 옆의 조용한 액션                    |
| `success`   | `#157845` | 잘 됐습니다                            |
| `warning`   | `#e2921c` | 안 될 수도 있습니다                    |
| `danger`    | `#c4383e` | 되돌아오지 않습니다                    |
| `info`      | `#186cb3` | 좋지도 나쁘지도 않지만 알아 둘 만한 것 |

## 손으로 고르는 값과 계산되는 값

계열마다 세 값을 적습니다. 그중 둘은 두 테마에서 동일합니다.

```css
--plass-primary-solid: #3558ef; /* 키 자신의 색 */
--plass-primary-on-solid: #ffffff; /* 그 위의 잉크 */
--plass-primary-accent: #2c49d6; /* 표면 위에서 읽히는 색 — 테마별 */
```

컴포넌트가 실제로 읽는 값은 전부 그 셋에서 파생 블록이 계산합니다.

| 토큰 | 계산 방식 |
| --- | --- |
| `--plass-{c}-fill` | 135° 그러데이션: `solid` +흰색 5% → `solid` → `solid` +검정 10% |
| `--plass-{c}-glow` | `solid`을 `--plass-glow-strength`만큼 (라이트 35%, 다크 55%) |
| `--plass-{c}-soft` / `-hover` / `-press` | `accent`를 10% / 18% / 26% |
| `--plass-{c}-line` / `-hover` | `accent`를 30% / 48% |
| `--plass-{c}-ring` | `solid`을 55% |

그래서 **색 계열 추가는 두 번의 편집입니다**. `PlassColor` union에 항목 하나, 그리고 `styles.css`에 두 줄과 테마별 `accent`.

## 키의 색은 테마를 따라 바뀌지 않습니다

`--plass-{c}-solid`와 `--plass-{c}-on-solid`는 모든 테마 블록 바깥의 `:root`에 한 번만 선언됩니다. **플라스틱 조각은 어두운 방에서도 같은 플라스틱 조각입니다.**

다크 모드가 바꾸는 것은 그 아래 바닥입니다.

| 토큰                     | 라이트                       | 다크                       |
| ------------------------ | ---------------------------- | -------------------------- |
| `--plass-glass`          | `white / 0.62`               | `white / 0.07`             |
| `--plass-glass-line`     | `white / 0.6`                | `white / 0.12`             |
| `--plass-shadow-ambient` | `rgb(20 40 90 / 0.16)`       | `rgb(0 0 0 / 0.5)`         |
| `--plass-glow-strength`  | `35%`                        | `55%`                      |
| `--plass-{c}-accent`     | 흰 배경에서 읽힐 만큼 어둡게 | 시트 위에서 읽힐 만큼 밝게 |

그림자를 키우는 대신 glow 강도를 올립니다. 거의 검은 페이지 위에서 색이 물든 그림자는 앉을 자리가 거의 없기 때문입니다.

## 대비

모든 `solid`는 하나의 숫자를 기준으로 골랐습니다. **그러데이션의 가장 밝은 지점이 자기 `on-solid`에 대해 4.5:1을 넘겨야 한다는 것.** 그 지점은 흰색 쪽으로 5% 들린 왼쪽 위 모서리이고, 채움의 밝기를 고정하는 것은 가운데가 아니라 그 모서리입니다.

라이트 테마에서 채움 위 라벨에 대해 측정한 값입니다.

| 계열        | 가장 밝은 지점 | 가운데 | 가장 어두운 지점 |
| ----------- | -------------- | ------ | ---------------- |
| `primary`   | 5.07           | 5.54   | 6.51             |
| `secondary` | 6.13           | 6.93   | 8.21             |
| `success`   | 4.99           | 5.52   | 6.66             |
| `warning`   | 6.05           | 5.80   | 4.72             |
| `danger`    | 4.65           | 5.27   | 6.46             |
| `info`      | 4.68           | 5.48   | 6.64             |

`warning`만 방향이 반대인데, 잉크가 어둡기 때문입니다. 거기서는 _가장 어두운_ 지점이 빠듯한 쪽입니다. 앰버라 부를 만한 어떤 밝기에서도 흰 글자는 4.5:1에 닿지 않아서, `--plass-warning-on-solid`는 이 세트에서 유일한 짙은 갈색입니다.

각 `accent`는 자신이 읽히는 배경에 대해 4.5:1을 넘깁니다. 라이트 테마에서는 밝은 wash, 다크 테마에서는 어두운 시트입니다.

## 계열 덮어쓰기

두 값을 아무 요소에나 설정하면 거기서 파생되는 모든 것이 따라옵니다. 파생 블록이 모든 테마 root에서 반복되고 `color-mix()`가 요소마다 풀리기 때문입니다.

```css
:root {
  --plass-primary-solid: #7c3aed;
  --plass-primary-accent: #6d28d9;
}

.dark,
[data-theme='dark'] {
  --plass-primary-accent: #c4b5fd;
}
```

바꿀 때 확인할 것 둘.

1. **가장 밝은 그러데이션 지점과 잉크의 대비.** 색을 흰색과 95%로 섞은 뒤 `--plass-primary-on-solid`에 대해 측정하세요. 4.5:1 아래라면 잉크가 아니라 solid를 어둡게 하세요.
2. **두 테마 모두에서 accent와 페이지의 대비.** _읽어야_ 하는 값입니다.

## 중립색

| 토큰 | 하는 일 |
| --- | --- |
| `--plass-surface` | 반투명할 수 없는 것을 위한 불투명 시트 |
| `--plass-fg` | 본문 글자 |
| `--plass-muted-fg` | 라벨, 설명, adornment |
| `--plass-border` | 유리 hairline이 어울리지 않는 자리의 중립 hairline |
| `--plass-bg-from` / `-to` | 유리를 튜닝한 기준이 된 페이지 wash — [시작하기](../guide/getting-started#컴포넌트-아래에-깔릴-페이지) 참고 |

`--plass-bg-from`과 `--plass-bg-to`는 라이브러리가 스스로는 절대 쓰지 않는 유일한 두 토큰입니다. 평평한 흰 페이지 위의 유리 시트는 앞에 세울 것이 없는데, 컴포넌트 라이브러리가 남의 `<body>`를 칠할 일은 아니어서, 색의 이름만 알려 주고 칠하는 일은 넘기는 것입니다.
